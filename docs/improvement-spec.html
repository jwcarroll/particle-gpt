01 / Mandate

Build confidence before breadth.

The next version should make the simulation reproducible, benchmarks honest, and renderer behavior intentional. New effects and forces become cheaper only after those foundations are explicit.

Primary success measure: an implementer can run the same declared workload twice, explain every material input, compare only compatible results, and obtain equivalent simulation behavior across rendering frame rates.

Scope

  • Simulation timing, population lifecycle, and deterministic input.
  • Renderer capability detection, common surface configuration, and high-DPI behavior.
  • Versioned benchmark manifests, exact scenario setup, restoration, and guarded comparison.
  • Self-describing built-in force and effect plugins.
  • A restrained full-canvas application shell with direct manipulation and sharable presets.
  • Tests, validation scripts, CI, and documentation that support progressive LLM discovery.

Non-goals

  • Changing from a browser application to a native engine.
  • Loading arbitrary third-party JavaScript or shader source at runtime.
  • Rewriting every module in one migration.
  • Claiming physically accurate fluid or rigid-body simulation.
  • Requiring exact pixel identity between Canvas2D and WebGL.
  • Introducing a framework solely to replace the current imperative UI.

03 / Findings

What can mislead or fail today.

Priority reflects correctness and trust, not implementation difficulty.

Resolved · First slice

Scenario counts are now guaranteed at start

Built-in scenarios now call World.resetPopulation(count, { seed }) before warmup, so fixed and ramp scenarios begin at their exact declared population regardless of prior UI state.

Resolved · Second slice

Physics timing is independent from render cadence

A DOM-free clock now advances physics at a fixed 60 Hz, retains bounded catch-up backlog, skips rendering when behind, and supplies interpolation alpha to every renderer. Emission uses simulated seconds, ramp failure uses elapsed milliseconds, hidden time is discarded, and affected benchmarks are invalidated.

P1 · Availability

Optional WebGL is a startup dependency

The WebGL renderer is constructed before renderer choice. Failure to create WebGL or the instancing extension can prevent Canvas2D from loading, even though Canvas2D is the default. Evidence: src/main.ts:52-63.

P1 · Comparability

Renderer runs are not equivalent

Canvas inherits the page background while WebGL clears opaque black. Device-pixel-ratio handling, color support, alpha state, and particle capacity also differ. Renderer benchmarks currently mix implementation cost with different visual work.

P2 · Evidence

Results omit workload-defining context

Saved results lack renderer, backing-buffer size, effects, complete force state, clock configuration, seed, thresholds, and code revision. The comparison path accepts mismatched runs and still produces a verdict.

P2 · Extensibility

Plugins remain manually centralized

Registries store state, but UI controls and shader uniforms require concrete imports and branching in the two largest files. State snapshots are shallow and restored through unchecked casts.

P2 · Semantics

Radial force is not a radial field

The force context provides only the swarm centroid, and the registry calculates one vector per frame. Every particle receives the same acceleration toward or away from the configured center.

P3 · Product quality

The instrument still presents as a scaffold

The title and favicon remain “Vite + TS,” desktop controls truncate tab labels, and the fixed 256-pixel inspector consumes roughly two thirds of a 390-pixel mobile viewport. There is no pause, step, reset, preset sharing, or direct canvas interaction.

04 / Target outcomes

Definition of success.

Deterministic

Identical seed, inputs, and simulated duration produce equivalent world state across common render cadences.

Comparable

Every benchmark carries a versioned manifest; incompatible workloads are rejected or explicitly labeled exploratory.

Resilient

Canvas2D works without WebGL. Renderer failures are localized, explained, and recoverable without changing simulation state.

Extensible

Built-in plugins declare state, units, controls, version, validation, determinism, and capability needs.

Operable

Users can pause, step, reset, select presets, manipulate the field, share a scene, and understand benchmark context.

Maintainable

Core behavior is unit tested; renderer and benchmark workflows have focused browser coverage; CI enforces the documented gates.

05 / Architecture direction

Separate the clock, world, surfaces, and evidence.

Introduce these boundaries incrementally. The arrows show intended dependency direction.

Domain code must not depend on DOM, Tweakpane, local storage, or renderer implementations. Controllers translate browser events and UI intent into domain operations. Benchmarking assembles an immutable workload and observes the same public controller/world interfaces used by the product.

06 / Workstreams

Implementation requirements.

Each workstream is independently reviewable, but the delivery order later in this document controls sequencing.

Foundation and safety net

  • Remove the package self-dependency without changing runtime behavior.
  • Add unit-test, lint, formatting, and CI scripts with documented Node support.
  • Cover vector zero-length behavior, particle lifetime/reset, registry snapshots, metric percentiles, and comparison compatibility.
  • Split the composition root only along implemented boundaries; do not begin with a broad rewrite.
Acceptance criteria
  • Clean install and production build pass in CI.
  • Tests are deterministic and do not require a browser for domain modules.
  • AGENTS.md and development commands match package scripts.
  • No generated output is committed.

Clock and population semantics

  • Implement the fixed-step, clamped, bounded-catch-up clock from ADR-0001.
  • Implement explicit reset, target, trim, and particles-per-second emission APIs from ADR-0002.
  • Inject a seeded random source for particle generation and deterministic plugins.
  • Pause cleanly on document visibility changes; benchmarks pause or invalidate rather than including hidden time.
Acceptance criteria
  • 60 Hz and 144 Hz schedules converge to the same state for a deterministic fixture.
  • A suspended tab cannot inject an unbounded world step.
  • Every benchmark scenario starts with its exact declared count.
  • Emission count depends on simulated seconds, not rendered frames.

Renderer manager and parity

  • Create renderers lazily and expose structured capability results.
  • Share logical size, device pixel ratio, background, clear behavior, and normalized particle colors.
  • Restore all Canvas context state and surface the WebGL particle ceiling.
  • Handle resize and WebGL context loss without mutating the world.
Acceptance criteria
  • The application remains usable when WebGL or instancing is unavailable.
  • Renderer switching preserves the exact particle state.
  • Effect-off reference scenes pass defined visual tolerances.
  • High-DPI backing buffers scale without changing world coordinates.

Benchmark integrity

  • Implement the versioned manifest and compatibility fingerprint from ADR-0005.
  • Unify complete and cancel cleanup paths and restore exact user state.
  • Replace frame-count timing windows with elapsed-time windows.
  • Validate imported JSON deeply and make unsupported versions view-only or migrate them.
  • Show configuration differences, sample quality, and individual metrics before any verdict.
Acceptance criteria
  • Renderer, viewport, DPR, clock, seed, forces, effects, thresholds, scenario version, and build identity are recorded.
  • Incompatible runs are rejected by default with visible reasons.
  • Zero-sample and interrupted runs cannot be saved as completed baselines.
  • Export/import round-trips without losing manifest fields.

Plugin contracts

  • Add stable kind and schema version, runtime validation, units, control descriptors, determinism metadata, and capability requirements.
  • Generate common controls through a UI adapter rather than plugin dependencies on Tweakpane.
  • Separate uniform forces from per-particle field forces; implement true attractor/repulsor behavior as per-particle evaluation.
  • Keep effect implementations trusted and built in; do not accept arbitrary shader text.
Acceptance criteria
  • Adding a normal built-in plugin requires catalog registration, not bespoke composition-root controls.
  • Invalid or unknown snapshot versions fail without partially applying state.
  • Uniform and per-particle evaluation costs are visible in benchmark manifests.
  • Preset snapshots and exact replay snapshots have documented differences.

Product shell and interaction

  • Replace Vite title/favicon and make the product identity visible without competing with the canvas.
  • Add play, pause, single-step, reset, seed, background, preset, and share controls.
  • Use a collapsible right inspector on desktop and an accessible bottom sheet on narrow viewports.
  • Add direct canvas tools for attractor, repulsor, vortex, and emitter placement.
  • Add optional trails and vector-field overlays, plus PNG capture; consider video capture only after the core is stable.
Acceptance criteria
  • The full canvas remains the primary workspace.
  • Core controls are keyboard accessible and usable at 390px width.
  • A shared URL recreates validated scene configuration and seed.
  • Reduced-motion preferences disable ornamental motion without affecting simulation controls.

07 / Experience direction

The canvas is the product.

The interface should feel like a calm scientific instrument: one workspace, one inspector, and one transport surface. Avoid dashboard cards and decorative chrome.

Global definition of done

  • No silent fallback, truncation, schema coercion, or incompatible benchmark comparison.
  • No per-frame allocation regression without measured justification.
  • No UI control whose label disagrees with runtime units or behavior.
  • Every failure path preserves or restores user state and produces an actionable message.
  • The final handoff lists commands run, observed results, skipped checks, and remaining uncertainty.

10 / Cold-LLM handoff

How to pick this up safely.

  1. Read repository-root AGENTS.md.
  2. Use docs/README.md to select only the task-specific references.
  3. Inspect git status; preserve unrelated user changes.
  4. Confirm current behavior in code. This specification is proposed target state, not proof of implementation.
  5. Read the relevant ADR before changing a contract. All ADRs begin as Proposed.
  6. Implement one coherent work package and its tests. Avoid combining tooling, physics, renderer, benchmark, and visual redesign in one change.
  7. Run the risk-appropriate validation from docs/development.md.
  8. Update documentation and ADR status only when the repository genuinely reaches that state.
